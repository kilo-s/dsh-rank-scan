# @dsh-external/dsh-rank-scan

DSH 扫榜插件（定时 + HTTP 路由 + 面板；**不注册 DSH 工具**）。说一句就扫，扫完在面板里看；不推送、不登录、不抓正文。

## 0. 快速开始（一页版，先看这个）

**装**（把 tgz 拷到目标机器，然后一条命令）：

```powershell
pwsh -File scripts\install.ps1 -Spec "D:\dsh-external-dsh-rank-scan-0.0.1.tgz"
```

（macOS / Linux 用 `bash scripts/install.sh desktop <tgz 路径>`；开发时用 `-Spec "link:<插件目录>"` 直装目录。）
装之前请**完全退出桌面版 DSH** —— `dsh plugin` 在桌面版运行时会被拒绝。

**验**：重开 DSH → 左侧栏会话列表下面应出现「扫榜」入口；或访问 `http://127.0.0.1:19387/api/rank-scan/health`，返回 `{ok:true,...}` 即通。

**卸**：`pwsh -File scripts\uninstall.ps1`（macOS / Linux：`bash scripts/uninstall.sh`）。卸载会清掉插件、路由残留与 junction，但**保留数据目录** `%USERPROFILE%\.dsh\data\rank-scan`（配置 / 书签 / 书页缓存都在里面）——想彻底清理自己删这个目录。

**侧栏没有「扫榜」入口怎么办**（按顺序看）：

1. DSH 启动日志里搜 `did not activate` 与 `pending (waiting for services`：前者 = 面板 bundle 没加载成功，后者 = 缺 timer / webServer 服务；
2. 访问 `/api/rank-scan/health`：能返回 JSON ⇒ host 侧活着，问题在面板；连不上 ⇒ 插件没装上；
3. 重装一次：`pwsh -File scripts\install.ps1 -Spec "<tgz>"`。

**数据与隐私**：只读站点公开榜单与书页，不登录、不抓正文、不推送；限速 1s/条、每天一轮（**定时默认开启**，安装当天不自动跑；可在面板「抓什么」页随时关掉，关掉后重载也会保留）。数据只在本机 `~/.dsh/data/rank-scan`，不外传。

> ⚠ **本插件不注册任何 DSH 工具**（2026-10-16 更正）：下面「现在能做什么」表里早先列的 `rank_scan` / `rank_diff` / `rank_clean` / `rank_export` 是模板期残留、**实际不存在**；对外能力只有 `/api/rank-scan/*` 路由 + 面板 UI。
> 同理，`src/client/index.ts` 那个 tsdown 脚手架已在 2026-10-16 删除 —— 面板就是手写的 `lib/client.js`，**不会再被构建覆盖**；profile 装配入口见 `cordis.patch.yml`（`dsh.bundle.patch`）。

## 用法

```json
// 立刻扫一次（默认「签约榜 × 轻小说」）
rank_scan {}
// 只扫某榜
rank_scan { "boards": "qidian.sign.cat12" }
// 顺带补收藏/精确字数（每本 1 请求，1s 间隔，会明显变慢）
rank_scan { "boards": "qidian.sign.cat12", "enrich": true }
// 只重跑当天失败的榜（不发新请求给已 ok 的榜）
rank_scan { "retry": true }
// 停止当前扫描（下一个请求间隙生效）
rank_scan { "action": "cancel" }
```

数据目录默认 `~/.dsh/data/rank-scan/`（可用插件配置 `dataDir` 改）：

```text
<dataDir>/<数据日期>/<boardId>.json   快照（rows + metric）
<dataDir>/<数据日期>/scan.json        本次扫描元信息（attempt / outcome / progress / 每榜状态）
<dataDir>/state/scan.lock.json        扫描锁（含心跳时间）
<dataDir>/state/retries.json          各榜当日重试次数
<dataDir>/state/cancel.json           取消标志
```

## 本机构建（重要：官方 `build.sh` 在这台机器上不可用）

`scripts/build.sh` 靠 **junction/symlink** 把 dsh checkout 的依赖链进 `node_modules`；本机沙箱**禁止 symlink**
（实测 `fs.symlinkSync` → EPERM、`fs.cpSync` → EIO；PowerShell `Copy-Item` 可以），因此
`dev_build_plugin` 会以「Linking build dependencies」后退出 1 失败。

本包因此设计成 **零运行时依赖**：host 侧不 import `@deepseek-ai/dsh-tools` / `schemastery`，
工具用普通对象直接 `ctx.tools.register({...})`；client 侧手写 `window.__ModuleLoader__.load({ id, factory })` 形态的 bundle（tsdown 未安装）。

构建与自测（本机）：

```powershell
# 编译 host（用 checkout 自带的 tsc，不建 junction）
powershell -File scripts/build-local.ps1

# 跑全部离线测试（node --test 会 spawn 子进程被沙箱拒 ⇒ 按文件直接跑）
powershell -File scripts/test-local.ps1
```

- `scripts/*.ps1` 必须带 **UTF-8 BOM**：不带时 Windows PowerShell 5.1 会按 GBK 读中文 → 解析报错；用 `pwsh`（PS7）跑也可以

注入 / 更新：

```text
dev_inject_plugin   { "dir": "<本目录>" }     # 首次
dev_reload_package  { "packageName": "dsh-rank-scan" }   # 改完重编译后热重载
dev_uninject_plugin { "match": "dsh-rank-scan" }         # 卸载
```

## 设计约束（改代码前先读）

- 词汇一律用 `docs/rank-scan/CONTEXT.md`（站 / 榜 / 快照 / 数据日期 / 变化集 / 抓取集 / 显示集 / 状态五态…）
- **缺失一律 `null`，绝不补 0**；日期取本地自然日（忌 `toISOString()`，北京时间凌晨会差一天）
- 采集纪律：限速 1s/请求、每日 1 次、失败重试 ≤2、原子写、同日覆盖
- ⚠️ **不要用 fs.cpSync 复制目录**：本机实测递归复制目录会 EIO Access is denied（导出在数据目录上直接失败）；
  一律逐文件 copyFileSync（scan/files.ts 的 copyDirDeep）
- 唯一测试 seam = `runScan({ sites, clock, store, budget, enrich })`：站点/时钟/存储/预算全部注入
- 数据目录与工作区无关；插件不写工作区内文件
## 面板（三个页签 · 可拖动可缩放浮窗 · 2026-10-14 按属主反馈重做）

- **浮窗**：标题栏拖动移动、右下角把手缩放，位置与尺寸存 localStorage（刷新后保持）；右上「收起」缩成小按钮。
- **概览页**：一行汇总（数据日期 / 基期 / N 个榜 / 全部正常或异常数 / 隐藏数 / 上次扫描）+ 按站分组的单表（**不再每站重复一遍表头**）；
  异常榜单独折叠区（点「展开异常 N 个榜」才列）；下方接「今天的变化」。无基准时涨/新/退一律「—」，**不报 0**。
- **当前榜单页**：站 → 榜 → 日期 → 排序四级控件；**「每榜取 N 条」输入框**（带出该榜当前值，保存后下次扫描生效）；
  **「补全数据（起点/番茄）」按钮**（见下）；点任意一行展开**行内详情卡**（书名/作者/字数/更新时间 + 「在站点打开」+「复制链接」）。
- **抓什么页**：站 → 榜种 → 分类 两级勾选（含「抓 / 显示」两列）+「恢复默认日常抓取」。**改动下次扫描生效**。
- **列口径（2026-10-14 属主定案）**：
  - 数值型榜**必带主指标列**：起点图首订=**首订**、番茄=**在读**、刺猬猫首订（约）=**首订（原始）**、派生榜=在读/对照读数
  - 起点：子分类 + **字数**（站点文本「10.09万字」）+ **收藏**（默认空，靠补全；空格显示「—」）
  - 起点图 三江：期初收藏 + **今日增量**（单列）+ 每日增量 + 已结算天数
  - 番茄：字数 + 在读（+ 有基准时的「在读变化」）；**已删「站方升降 / 更新时间」**（属主点名不要）
  - 刺猬猫 / 菠萝包：核心列；菠萝包另有评分/字数/收藏（**只有前 2 名有值**，空格「—」）
  - **「在榜天数」只在真有历史时不占列之外才出现**（当天无历史 ⇒ 整列不出现，不留一列「—」）
- **补全数据（enrich，按需手动）**：
  - 起点：逐本反查书页 ⇒ 精确字数 + 收藏（适配器内置 enrich，1 请求/本）
  - 番茄：逐本打 `/api/book/info` ⇒ **干净书名/作者**（榜单接口本身因字体反爬缺字；接口不吐书名时回退抓书页 og:title）
  - 结果**就地覆盖当天该榜快照**与 scan.json（幂等，可重复补）；刺猬猫/菠萝包**暂不支持**（会明确回话，不静默）
- **跳转**：DSH Web GUI **没有内嵌浏览器/侧栏浏览器槽位**（已查：无 browser-in-sidebar API 与"在线浏览器"入口），
  所以点书名**不会**在 DSH 侧栏里打开；现方案 = 行内详情卡 + 「在站点打开」（新标签）+ 「复制链接」。
- 宿主路由（同源、只读本地快照，**渲染不联网**）：

- ⚠️ **路由前缀不得带尾斜杠**：宿主 match() 的规则是 pathname === prefix || pathname.startsWith(prefix + '/')，
  所以带尾斜杠的 '/api/rank-scan/' **永远匹配不到** '/api/rank-scan/overview'（会被更短的 '/api' 抢走，症状是全站 404 not found）。
  注册必须用不带尾斜杠的 '/api/rank-scan'，handler 内再对 pathname 归一化尾斜杠。
- ⚠️ **webServer 服务要晚绑定**：运行时注入的实例上直取 ctx.webServer 拿不到，要用 ctx.inject(['webServer'], …)（见 dsh-genui 的做法）
- 宿主路由（同源、只读本地快照，**渲染不联网**）：
  - `GET /api/rank-scan/overview` 概览：数据日期 / 基准日 / 五态计数 / 隐藏榜数 / 每站每榜状态与涨新退 / 按站编组
  - `GET /api/rank-scan/board?boardId=&date=&sort=` 当前榜单：列随榜、缺失显示「—」、当天没快照时回落最近可用并标注日期
  - `GET /api/rank-scan/changes` 今日变化：按站编组，组内固定 新入榜/回榜/上升/下降/退榜；无基准时写「首次扫，无基准」不报 0
  - `POST /api/rank-scan/scan` / `cancel` / `retry` 三个动作按钮
  - `GET /api/rank-scan/health` 自检：路由是否挂上（返回 port / 数据目录 / 数据日期列表）
  - `GET /api/rank-scan/catalog` 可选榜清单：站 → 榜种 → 分类 + 是否已勾选/已显示 + 各榜深度
  - `POST /api/rank-scan/select` 抓取集/显示集（body: {captures?:[], displays?:[]}）
  - `POST /api/rank-scan/depth` 每榜取数（body: {boardId, depth}，1–100）
  - `POST /api/rank-scan/enrich?boardId=` 按需补全该榜当天快照字段（起点/番茄）
- 客户端：`lib/client.js`（手写 `window.__ModuleLoader__.load({ id, factory })` bundle，仅用平台 react；注册到 `shell.overlay` 槽位，右上角「扫榜面板」）
- ⚠️ **客户端改动后需要刷新 GUI 页面**才生效（host 侧改动用 `dev_reload_package` 即可）

## v11.1 · 起点图历史日期仍然为空：**日期没补零**（2026-10-15 属主截图）

**v11 修了「永远抓当日」，但历史日期还是空。** 属主截图显示：日期选 2026-10-01、点「直接查看」，
结果是 0 行 + 一条容易误导的说明。

**根因**：URL 被拼成了 `/shouding/2026-10-1`（**日没补零**）。站点对这个路径返回 **200 + 26 字节空页**
⇒ 解析出 0 行 ⇒ 抛出「该日期无数据」，于是看着像「站点没这天的数据」。

| 请求 | 状态 | 字节 | /info/ 链接 |
|---|---|---|---|
| `/shouding/2026-10-1` | 200 | **26** | 0 |
| `/shouding/2026-10-01` | 200 | 172849 | 291 |

**修法**：统一走 `ymd(date)`（`src/sites/qidiantu.ts` 导出，内部 `padStart(2,'0')`），
适配器里三处手工日期串全部换掉。**实测**：`/day 2026-10-01` → **287 行**（首本 神宠供应商）、
`10-05` → **5 行**、`10-11` → **15 行**、`10-14` → **62 行**，各日期结果互不相同 ✅

> 附带发现：这个「未补零 ⇒ 空页」的坑在**手工编辑源码时又被我踩了一次** —— `tools.edit` 对
> 「`String(d.getDate()).padStart(2,'0')`」这类**行尾长表达式**做替换时很容易把尾部吞掉。
> 现在有单测钉住（`ymd(2026-10-01) === '2026-10-01'` + 断言路径里不出现 `/\d{4}-\d-\d`）。

### 同时修掉：首订页的「作者」恒为空

首订页第 7 格是 `等级 作者`（如 `Lv.5 骆驼祥爷！` / `白金 轻泉流响`），而原实现去匹配
`/author/` 链接 —— **首订页根本没有这种链接** ⇒ 作者列永远空。现在从第 7 格去掉等级前缀取作者，
`/author/` 链接只作退路。实测：赤羽老师 / 宇智波番长 / 骆驼祥爷！ 都出来了。

### 「抓取并存入本地」会跳回最新 —— 已改

原因：存盘后调 `reloadBoard()`，而「日期」下拉的状态 `sd` 还是空 ⇒ 按**最新**重新取。
现在存盘后把 `sd` 设为该日期（由 `useEffect` 触发带 `date` 参数的刷新）；
「直接查看」也把该日期临时补进下拉选项，两种方式都能在界面上看出「在看哪天」。
**实测**：存 2026-10-11 后，日期下拉 = 2026-10-11，表格 15 行、首本「同时穿越…」✅

## v11 · 四项修复（2026-10-15 第四批反馈）

### 1. 起点图历史日期直查**根本没按日期查**（真 bug，最严重）

**症状**：日期下拉里不同日期显示的作品**完全一样**。

**根因**：`sites/qidiantu.ts` 里读 `ctx.dateOf` 决定要不要拼日期路径：

    const want = (ctx as any).dateOf as string | undefined
    const url = want && want !== todayStr ? '.../shouding/' + want : '.../shouding/'

但 **`dateOf` 在整个仓库里没有任何地方被设置过**（`grep dateOf` 只有这一处读取）⇒ `want` 恒为 `undefined`
⇒ **永远请求当日 `/shouding/`**。于是「直接查看 10-11」拿回的是今天的榜 —— 数据没变，所以看着像「都一样」。

## v10.3 · 「期累计」按已有数据窗口起算（2026-10-15 属主质疑）

**属主的问题**：番茄周榜的「期累计」为什么不按**已有数据**的七天快照统计？

**查证**：本期 10-12 ~ 10-18，但数据是从 **10-14** 才开始抓的 —— `2026-10-12` / `2026-10-13`
本地**根本没有快照**。原实现硬拿期首（周一 10-12）当基准 ⇒ **整榜 240 行期累计全是「—」**，一行有用的都没有。
属主的质疑成立。

**改法**（`derive.ts`）：期累计基准日 = **期首优先**，**期首缺快照就退回「本期内最早有数据的日期」**：

    const baseDate = valueAt(key, periodStart) != null
      ? periodStart                                            // 期首有快照 ⇒ 标准口径
      : (dates.find((d) => d < today && valueAt(key, d) != null) || null)  // 期首缺 ⇒ 退回最早数据日
    const periodDelta = v != null && bv != null ? v - bv : null

- 实测首行：`210819 − 185463 = 25356`（基准日 10-14）✓ 有值的行 48/240（只有 10-14、10-15 都出现过的书才算得出）
- **必须标明基准被推后**：`extra.baseDate` / `baseIsPeriodStart` 一起回传，说明行写
  `⚠ 期首 2026-10-12 没有快照，「期累计」按本期内最早有数据的 2026-10-14 起算`。
  否则用户会以为「期累计」是整周的量，其实只是两天的量。
- 语义澄清：**基准日 == 今天 ⇒ 期累计 0**（本周内还没涨，是事实，不是缺失）；只有**今天才入池**（期内没有更早的自己）才是 `null`。
- 等 10-19 起有「整周期」数据后，基准自动回到周一，说明行里的 ⚠ 自动消失（逻辑不变，只是条件不再命中）。

**为什么不用「最近 7 个已有数据日」（滚动窗口）**：那正是 v10 退掉的口径 —— 每本书基准是它自己 7 天前那条，
入池晚的书天然吃亏，**横向不可比**。固定期首才是可比的根基，所以这里只在「期首确实缺快照」时退让一步，并显式标注。

**属主的疑问**：「今天周四，从周一算不该是结算 3 天吗？」

  `本周已结算 2/7 天（周一~周日；有数据的日期：10-14、10-15）。⚠ 周一~今天应已过 4 天，缺的那几天本地没有快照（不算结算）`

## 番茄派生榜改「自然周」口径（v10 · 2026-10-15 属主定稿）

**动作**：两个派生榜（`fanqie.derived.delta` 在读涨幅榜 / `fanqie.derived.week` 七日累计）
**合并为一个** `fanqie.derived.period`「在读周榜（候选池内）」，旧的**退掉**。

**为什么必须落固定周期**（属主提出的关键问题）：
- 滚动「最近 7 个数据日」：每本书的基准是**它自己** 7 天前那条 ⇒ 入池 3 天的书只有 3 天涨幅，
  却和入池 5 年的书同榜比，**横向不可比**；
- 「从入池起累加每日涨幅」在数学上 **恒等于今天的在读数**（自己 − 自己入池那天），等于没做统计；
- ⇒ 照搬 **起点图三江榜**的口径：**同一期首日 + 期内累加每日增量 + 已结算 N 天**，
  全站共用同一个基准日，N 本书才可比。

**周期定义 = 自然周（周一~周日）**（属主选 A）：
- 期首 = 该周周一（`weekStart()`，本地时区）；面板「基期」显示的它就是期首；
- `本期累计 = 今日在读 − 期首在读`；期首当天入池/期中入池 ⇒ `null`（显示「—」，不伪造 0）；
- `已结算 N/7 天`：照搬三江的「已结算天数」，一眼看出这期数据够不够；
- **0 额外请求**（全部从已落盘快照算），与采集纪律一致。

**列与排序**（属主 2026-10-15）：
- 列：`名次 / 书名 / 作者 / 在读 / 今日涨幅 / 本期累计 / 已结算`；
- **默认名次 = 今日涨幅倒序**；排序项另给 `今日涨幅 / 本期累计涨幅 / 在读`（都是倒序）；
- 不出「在榜天数」（派生榜没有快照，且与「池内天数」重复）、不出「日期」下拉（派生榜总是算最新一期）。

**口径选择（值得记住的边界）**：「今日涨幅」的比较基准也**落在期内**，不跨期去取上一期最后一天。
否则周一那天会出现「本期累计 = 0」而「今日涨幅 = 200」的自相矛盾。代价：**每周一所有书的「今日涨幅」都是「—」**
（诚实表达「本周还算不出涨幅」）。

**迁移**：`readState()` 里有幂等迁移 —— 看到两个旧 id 就换成 `fanqie.derived.period` 并写回 config.json
（否则「抓什么」看不见新榜、保存时又把旧的写回去）。默认抓取集也加了它，**新安装默认就有**。

**测试**：`tests/derive.test.mjs` 重写为 7 条（自然周边界 / 默认名次与累计 / 期中入池 / 期首当天 / 跨周 / 多榜并集 / 只派生一个榜）。

## 「在榜天数」统一口径（v9.6 · 2026-10-15 第五轮反馈）

**现象**：起点只有「轻小说(cat12)」有在榜天数，其它子分类没有；番茄部分分类也没有。
看起来像「分类之间没统一」，实际是**两个叠在一起的 bug**：

1. **列的出现条件是错的** —— `shouldShowDays(site, priorDataDatesForBoard)` 要求「该榜有 **≥2 个数据日**」。

   **改成 `historyFromSnapshots(boardId, effDate)`：直接遍历该榜自己的快照文件累积历史**，与抓取集/交付时间无关。

## 定时扫描与面板弹出（v9 · 2026-10-15）

### 定时扫描的三条硬约束（★ 2026-10-15「重启即重扫」事故后的修法）

事故：定时触发只看 `dueNow`（过了扫点 + 当天没扫过），而「当天跑过没」记在**进程内存**里
⇒ 宿主每次重启都重新判成「该扫」⇒ 重启 → 立刻补跑整站扫描 → 宿主又挂 → 再重启的自我循环。
（当日实测：5 次重启，每次启动后 2 秒起一轮 17 榜 + ~90 请求补全。）

现在必须三条同时成立才允许触发（判据在 `src/scan/schedule.ts#shouldFireTimer`，纯函数 + 单测）：

| 约束 | 落点 | 防的是什么 |
|---|---|---|
| ① 「今天跑过没」**落盘**（`state.lastTimerRun`） | `defaultState` + `checkTimer` 写回 | 重启后继续记得今天已扫过 ⇒ **重启不重扫** |
| ② 启动宽限期 `freshMs`（默认 5 分钟，插件配置 `timerFreshMs` 可改） | `freshMs` 入参 | 宿主刚起来不抢资源（启动期竞态） |
| ③ 无「翻开关」迁移（2026-10-16 最终口径） | `bindTimer` | **默认开、用户可关、重载保留**：除面板 /timer 接口外任何代码都不写 `timerEnabled` |

> ★ **2026-10-16 修（属主：「我明明打开过定时，谁关的」）**：③ 的判据原来是 `timerSchemaV !== 2`，
> 但同一次迁移又把戳写成 **6**（后面的 v6 迁移）⇒「6 !== 2」恒真 ⇒ **之后每一次启动都把用户的开关重新关掉**
> （`timer.log` 里就是那行「一次性迁移：老配置的定时开关已置为关闭」在每次注入后重复出现）。
> 判据已钉在「字段缺失」上：新装的 config 由 `defaultState` 写的就是 6，不会再被误关；老机器首次启动字段确实不存在 ⇒ 仍只关一次。

其它：新安装 `timerEnabled=false`（面板里自己开）；同进程内**定时/手动共用一把锁**（定时在跑时 `POST /scan` 回 409）；
面板「抓什么」页用 `POST /api/rank-scan/timer {enabled, scanTime}` 设置，`GET /catalog` 回读 `timer{wired,lastRun,lastState,inFlight}`。
诊断入口：`<dataDir>/state/timer.log`（接线/迁移/每轮开始结束各一行）。

### 面板弹出的时机

- **安装成功后第一次打开 DSH 自动弹一次**（`localStorage['rank-scan-panel:autoopened:v1']` 不存在时弹，并立刻打标记）。

### 起点收藏与书页缓存（v9 · 2026-10-15）

- **起点收藏默认关**（`state.qidianEnrich=false`）：榜单页给不了，只能逐本进作品页。面板「抓什么」页有开关，勾上才补。
- 成本靠 `<dataDir>/state/qidian-book-cache.json` 压：**同一本书在 TTL（默认 7 天）内不重复下载** 103 KB 页面。
  命中 ⇒ 0 请求；未命中/过期/新入榜 ⇒ 1 请求（1s 限速）。
- 缓存只存书页**真能给**的字段：`collect` / `wordsCnt` / `title` / `fetchedAt`；**拿不到 `collect` 的结果不写缓存**（避免把失败固化成空值）。
- 单次补全有请求上限 `qidianEnrichBudget`（默认 25）兜底：超了剩下的下次继续收，不会一次打穿。
- 入口：面板按钮「补全起点收藏（只打没缓存的书）」/「清空书页缓存（强制重抓）」；API `POST /api/rank-scan/qidianEnrich`、`POST /api/rank-scan/qidianCache {clear:true}`；
  `GET /catalog` 的 `qidian` 段回读 `{enrich, cache:{books,newest}, ttlDays}`。
- 勾了开关后，**定时与面板「立刻扫一次」都会在扫描后自动补起点**（走上面同一套缓存，且只补本次扫描范围内的榜）；单榜重抓不补。

### 周期榜换期（v12 · 2026-10-16）

三个周期榜的「期」怎么走、换期当天会发生什么：

| 榜 | 期是什么 | 换期 | 空期保护 | 跨期保护 |
|---|---|---|---|---|
| 起点图 **三江·推荐效果** | 每周一期，**期首日 = 周日**（URL `/bang/1/6/<期首日>`） | 本地按数据日算出本期期首 | **有**：当期 0 行 ⇒ 自动退上一期，最多退 2 期，退成功记警告「本期（期首 X）无数据，已回退到上一期（期首 Y）」；三期全空才判 missing | **有**：跨期当天的变化列判为不可比 |
| 刺猬猫 **首订（约）** | 第三方接口的 `issue` 期号 | 第三方自己滚期 | **有**（原有）：当期空 ⇒ 退上一期，最多 2 期 | **有**：期号不同 ⇒ 名次变化不可比 |
| 番茄 **在读周榜** | 自然周（**周一~周日**），纯本地派生（0 请求） | `weekStart` 算本周一 | —（不依赖站点换榜） | **有**（原有）：今日涨幅/逐日增量的比较基准都落在期内，不拿上一期的日子当基准 |

**跨期不可比（v12 新增）**：变化列一律拿「上一数据日」当基准，而周期榜**换期当天**上一数据日属于**上一期**
——三江的总增量是「本期累计」、刺猬猫首订(约)的名次是「上一期那一榜上的位置」，两者相减得到的数字
**看起来真实、含义却是错的**。判据用**快照里记的真实期号**（三江 `extra.periodStart` / 刺猬猫 `extra.issue`），
不用本地日期推算；推不出期号的老快照保守判「不可比」。不可比时：

- 变化列**置空**（行上带 `extra.periodChanged`，面板显示「新期」）；
- 榜说明行写明「⚠ 本期已换期（期号 X → Y）：『变化』列跨期不可比」，口径跟着数据一起走；
- 非周期榜（起点/番茄分类榜/菠萝包等）行为**完全不变**（照旧环比）。

实现：`src/scan/diff.ts#guardCrossPeriod`（纯函数 + 单测）、`sundayOf`（本周日）；`src/sites/qidiantu.ts` 的
三江分支；闸门探针见 `scripts/acceptance.ps1` 的「周期榜换期」四组。
